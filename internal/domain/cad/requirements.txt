# The CAD kernel's Python packages, pinned exactly. The ONE list of them:
# `make cad-venv`, deploy/Dockerfile and the CI kernel job all install from here.
#
# Why pinned: build123d names ranges, not versions, so an unpinned install gets
# whatever PyPI holds that day. OpenCASCADE is the geometry — a new release can
# change a volume, a fillet that builds, or a STEP file — and the kernel tests
# only prove the version they ran against. Until Phase 4 stage K0
# (docs/plan-2026-09-13-millions-of-parts.md) a laptop, CI (which did not run
# the kernel at all) and the production image could each hold a different one.
#
# What this pins is what was running when K0 landed (2026-09-14): the image
# deployed as forge:a8993bb (Python 3.13, arm64) and the development venv
# (Python 3.14) both had build123d 0.11.1 on cadquery-ocp-novtk 7.9.3.1.1.
# Every line resolves to a wheel for Linux x86_64 and aarch64 (glibc 2.36+,
# Python 3.13 and 3.14) and for macOS arm64.
#
# Installed with --no-deps and followed by `pip check`: every dependency must be
# listed here, so a package that is missing fails the install loudly instead of
# floating to whatever PyPI resolves.
#
# To upgrade: change the versions here, run `make cad-venv test-cad` and the
# drills (scripts/drill-fences.sh), and let CI's kernel job run on the PR.
