# FORGE

**一个可持久化、长时运行的 AI 工程伙伴。**

FORGE 建立在一条核心原则之上：

> **长时运行的 Agent，不应该是一次长时运行的 LLM 调用。**

它是一套持久化工作流系统：模型反复被唤醒，从数据库重建自己的状态，执行**有边界**
的一小段工作，持久化结果，然后安全地在之后继续 —— 跨越崩溃、重启、发布和模型故障。

```
用户目标 → Planner → 持久任务库 → 队列/调度器 → Agent Worker
             ↑                                        ↓
             └────── 重规划 ←── 检查点 ←── 校验 ←──── 工具
```

`Agent = 模型 + Harness + 持久状态 + 工作流引擎 + 工具 + 调度器 + 恢复 + 评测 + 可观测性`

产品定义（语音优先协作、项目模型、风险分级、领域包、人类权威模型）见
[`docs/prd.md`](docs/prd.md)；架构见 [`docs/architecture.md`](docs/architecture.md)。

## 快速开始

**依赖：** Go 1.26+、Docker（用于本地 Postgres）、`make`。

```bash
git clone https://github.com/damonleelcx/J.A.R.V.I.S.-agent.git
cd J.A.R.V.I.S.-agent

cp .env.example .env
# 填入两个必需的密钥：
#   FORGE_SESSION_SECRET   openssl rand -base64 48
#   FORGE_LLM_API_KEY      你的 DashScope（通义千问）API Key

make db-up          # 在 :55840 启动 Postgres
make migrate        # 应用 schema（幂等，可重复执行）
make health         # 确认连通性
make check          # 格式检查、vet、完整测试套件
```

`make help` 列出所有可用目标。

## 读代码前值得知道的几个设计决策

### 迁移链在每次启动时全量重跑

`db.Migrate` 在**每次启动**时应用**全部**迁移，而不是跳过账本里标记为"已应用"的那些。

**为什么。** 数据库里的真实 schema 才是真相源，账本只是记录、不是权威。
如果某条 DDL 其实回滚了、账本却写着"已应用"，这条真正需要跑的迁移就会被永久静默地
抑制掉 —— 不做人工干预根本救不回来。全量重跑还有一个额外好处：幂等性在每次启动时
都被真实执行一遍，所以一条不可重复执行的迁移会在**下一次有人重启时**就暴露，而不是
几个月后在故障恢复现场才炸。

代价是每次启动多几毫秒的空转 DDL。`TestMigrationsAreIdempotent` 会对真实 Postgres
连跑三遍并比对完整 schema 快照 —— 它同时能抓住"重跑报错"和更隐蔽的
"两次都成功但 schema 不一致"。

### 校验模型与执行模型来自不同厂商家族

PRD **SAF-03** 要求：高风险结论必须由**独立于生成路径**的方法来校验。
让一个模型给自己的输出打分，不叫独立。因此 `FORGE_LLM_VERIFIER_MODEL` 默认
与 `FORGE_LLM_EXECUTOR_MODEL` 属于不同厂商家族，当两者同族时 `config.Load` 会告警。
这是一条以配置形式表达的**安全控制**，不是成本优化。

### 错误码和事件名只有一个来源

每个对运维可见的失败都带有稳定的错误码、原因，以及**强制要求的修复建议**。
一个无法告诉读者"下一步做什么"的失败就是死胡同，而死胡同正是长时运行的 Agent
在凌晨三点把人晾在原地的方式。

两个注册表都由**解析本仓库源码**的围栏测试守护，而不是靠列举自己要检查的对象。
一个"遍历自己所检查内容"的围栏是真空的：删掉一条只会让循环少转一圈。

### 遗忘必须扛得住一个还在不断学习的 agent

FORGE 会自己写记忆。所以用户删除一条记忆不能是 `DELETE`：下一个周期只要再次
观察到同样的事实就会把它原样写回去，而且没有任何地方会报告这次删除已经被撤销。

因此被遗忘的条目会保留行和 key，只丢掉值。key 继续占着该层的唯一索引，之后任何
对它的写入都会以 `MEMORY_FORGOTTEN` 被拒绝——agent 自己的工具和 API 一视同仁。
保留下来的只有「谁提出的、什么时候、为什么」；内容本身被清空，因为用户要的就是
忘掉内容。

重新放开这个 key 是另一条命令（`forgectl memory purge`），以 WARN 记录日志，并且
拒绝作用在一条从未登记过删除的条目上——否则它只是换了个名字的无记录删除。

### 不能让 FORGE 自己声明它是怎么知道的

`memory_remember` 工具没有「认知来源」这个入参，这是设计本身而不是遗漏。一个接受
`"how": "observed"` 的工具一定会拿到这个值，而这个标签的可信度，恰好等于当初那条
被捏造出来的 NEMA 17 螺栓孔位——一个组件不能给自己当守卫。

所以标签由那一刻唯一结构上成立的事实推导出来：模型主动写下的事实，是它从上下文
得出的结论，也就是 `inferred`。召回时再逐条返回 `may_be_acted_on`，而不是让模型
自己解释自己的标签。更强的标签必须来自可核验的东西——某个工具真实的输出、某个真的
被读过的文件——那会是另一个工具，而不是一份更宽的入参 schema。

### 节点的 kind 永远不变

一条后来被证实为真的假设，不会因此变成需求。改一个字段就能做到，但那是错的：把它
标记为「假设」的全部价值，就在于以后有人能问**我们究竟在哪些猜测之上继续搭了东西**
——而要回答这个问题，那条假设必须还在。

所以「提升」是新建一条需求，画一条 `derives_from` 边指回那条假设，并把假设保留下来，
状态置为 retired 而不是删除：不再生效，但仍然可读。两件事同时为真，这才是实际发生
的事。

编辑接口上没有 `kind` 字段，仓储层也没有 `UpdateKind`。拒绝时会直接告诉你替代做法，
而不只是说「不行」。

这和决策的 supersede、以及审计链是同一条规则：历史只增补，不改写。

### 「测试通过了」和「有人接受了」是两列，不是一列

每个产物版本同时带两个字段：verification state 是机器查出来的结论，human
disposition 是人做出的决定。二者互不推导，`Usable()` 要求两者都成立。

合成一列会更简单——直到某天一套通过的测试把它置成 accepted，于是这条记录就在声称
「有人签了字」，而其实没有任何人看过。PRD **SAF-05** 规定 AI 的批准永远不构成有效
授权；这就是那条要求在存储层的落地。

同样的切分贯穿图谱的 review：它把项目**自相矛盾**的地方和**尚且缺失**的地方分开报告，
只有矛盾会让检查失败。任何真实项目都有还没被验证的需求，而一个永远飘红的检查，一周
之内就会被人关掉。

### 语音界面是移动，不是缩水

工作台只有一个语音组件，但有两个位置。在还没有东西可看之前，它以完整尺寸占据舞台中央
——光球、字幕、状态词、麦克风和输入框——因为那一刻对话本身就是产品。第一次生成几何体
时，它移动到左下角，模型接管舞台。

两个位置能做的事完全一样：麦克风、输入框、免提、停止朗读。PRD **AUD-06** 要求每个关键
交互都有非语音路径，**AUD-07** 要求停止随时可达，所以紧凑不等于阉割。它是同一个 DOM
元素换了 `data-place`，不是两个需要互相同步的组件。

正中央是 FORGE 本人——`assets/portrait/` 里的角色立绘，右下角别着状态徽记，两者都由服务端
提供，这样"哪个状态对应哪张脸"这条规则只存在于 `persona.ExpressionFor` 一处。她身后的
canvas 只画**光晕**：辉光、波形和两道环。早先的版本曾在这块 canvas 上用矢量路径重画了徽记
的三片刀刃——那等于给一个只该有一个来源的身份又手工维护了一份副本，已经删掉。

徽记和下方的状态词说的是两件事，这是有意的。徽记用徽记自己的词汇表达 FORGE 的状态：模型
调用进行中是 `thinking`，有提案在等人拍板是 `blocked`，其余是 `idle`。这里永远不会用
`working`——它的含义是"进程之外有工具正在运行"，而这个页面上没有任何东西在做那件事。下方
的词表达的是语音界面自己的状态——收听、朗读——那是另一套词汇，不会去借用前者。

波形由真实测量驱动——麦克风流上的 `AnalyserNode`——但**只在收听时**。其他状态下
没有可测量的东西，所以动效是缓慢对称的呼吸，而不是语音产生的那种参差波带：装饰不能画成
读数的样子。测量流随每次收听开启和关闭，而不是一直持有，这样没人按住按钮时操作系统的
麦克风指示灯就是灭的。不能因为一个视觉效果，让一条隐私性质不再成立。

### 从工作台启动工作需要按两次

对话可以提议工作，但不能启动工作。

"Start this" 调用 `POST /v1/goals`，写入一个**草稿**目标并规划它。任务不可被领取，worker
碰不到它，而规划结果——每个任务、风险等级、哪些需要审批闸门——会返回并展示出来。只有在
这之后，第二个按钮才调用 `POST /v1/goals/{id}/start`。

显而易见的"一个接口搞定"方案被否决了：PRD **AGT-02** 要求实质动作之前必须有限定范围的
计划与预览，**AGT-04** 禁止在用户看不见的情况下提升自主等级。一次调用会把创建计划和启动
执行压进同一次按键，按下按钮的人等于批准了一份自己从没读过的任务清单。

`forgectl goal new` 和 `forgectl goal start` 就是同样这两步，两个入口共用同一个
`agent.Intake`，所以终端和浏览器对"未指定的目标默认是什么"不会产生分歧。激活会以
`goal.activated` 记入时间线，actor 是 `human` 并带账号 id——PRD **AGT-07**：有后果的状态
迁移必须带上具名的人类授权。在此之前，这个迁移什么都不写。

处于 active 的目标仍然只在有 worker 运行时才会执行。界面会直说这一点，而不是让 "active"
自己去暗示"正在推进"。

### 是七道限制，不是一道

Agent 会沿着七条彼此独立的轴失控：迭代次数、工具调用数、token、成本、墙钟时间、
任务深度、任务总数。只限制其中一条等于没限制。七条全部在 `EngineConfig` 里，
并在启动时校验。

## 目录结构

```
cmd/forgectl/            运维 CLI：migrate、health、config、version
internal/platform/       跨领域基础设施
  config/                环境变量加载与校验
  db/                    Postgres 连接池、事务、迁移执行器
  db/sql/                迁移链（编译进二进制）
  errs/                  中央错误码注册表
  logx/                  结构化日志与事件名注册表
  id/                    带前缀、可按时间排序的标识符
  clock/                 可注入的时间源
docs/                    PRD、架构、决策记录
```

迁移通过 `//go:embed` 编译进二进制，且只存在于**一个**目录。
一个需要依赖同级目录才能跑迁移的二进制，就是一个可能被部署成"起不来"状态的二进制。

## 在 Go workspace 内构建

如果你把本仓库 clone 到一个存在上层 `go.work` 的目录树里，直接 `go build ./...` 会失败：

```
directory ... is contained in a module that is not one of the workspace modules
```

`Makefile` 已经设置了 `GOWORK=off`，所以 `make` 目标在两种情况下都能正常工作。
临时命令请自行前缀：`GOWORK=off go test ./...`
