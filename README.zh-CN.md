## FORGE 是什么

大多数 AI 工具是**回答**你。FORGE 是**和你一起干活** —— 跨越几小时、几天，围绕同一个
项目，记得住当初决定了什么、以及为什么这么决定。

你描述一个支架、一副底盘、一栋小工作室的体量。它会先问工程师在动笔前会问的那些问题，
给出两三个**实质不同**的方案和各自的取舍，然后开始造 —— 可以转着看的几何体、图、文件、
检查项、遥测数据。不确定的地方它会说不确定；没核验过的东西，它拒绝叫"已核验"。

整个产品建立在一句话上：

> **长时运行的 Agent，不应该是一次长时运行的 LLM 调用。**

所以 FORGE 不是一个记性好的聊天框。它是一套持久化系统：模型被唤醒，从数据库重建自己的
状态，做**有边界**的一小段工作，存下结果，然后安全地在之后继续 —— 跨越崩溃、重启、
发布和模型故障。说到一半关掉标签页，明天回来接着说：它从**结构化检查点**恢复，而不是
从一段聊天摘要恢复。

## 一次真实的协作长什么样

**你说话。** 全双工语音 —— 说到一半打断它，它会立刻停下，保住项目状态，接住你的话头。
所有功能同时都能用键盘和文字抵达；小屏幕上语音界面是**移动位置**，不是缩水成一个次等版本。

**它会先顶回来，再动手。** 它会问这东西是干什么用的、装在哪、受多大力。对于低风险的探索，
它会带着**明确标注的假设**往前走，而不是把你审问一遍 —— 而那个标注会一直跟着它产出的东西。

**工作成果就长在对话旁边。** 一块画布，几个面板：

| 面板 | 落在这里的东西 |
|---|---|
| **Model** | 实时 3D —— 转、剖、爆炸、测量，多个变体并排对比 |
| **Diagram** | 结构与关系 |
| **Files** | 它写了什么，带 diff |
| **Checks** | 实际跑了什么，原始输出说了什么 |
| **Telemetry** | 数值，带着单位和坐标系 |
| **EDA / Simulation** | 明确声明，并诚实说明这套部署到底有哪些适配器 |

**没有任何东西能拿到比它应得的更好听的词。** *proposed*、*approved*、*running*、
*failed*、*completed*、*verified*、*accepted*、*released* 是八个不同的状态，FORGE 绝不
暗示自己处在其实没到的那一个。照片级渲染会被标注成"渲染图"：好看不等于可制造、结构够用
或合规 —— 而且这句话就写在图上。

**权威在你手里。** 任何有后果的动作都走 预览 → 审批 → 回滚，而审批必须**记名到人**。
"AI 批准了"永远不是"谁签的字"的合法答案。

## 六条承诺

这些是产品行为，不是愿景 —— 每一条都在代码里被强制执行，并且有围栏测试：这条承诺一旦
不再成立，测试就红。

| | 承诺 | 它排除掉了什么 |
|---|---|---|
| 1 | **它会说自己是怎么知道的。** 每条结论都标注为：观测 / 检索 / 计算 / 仿真 / 推断 / 假设 / 提议。 | 一句听起来很笃定、其实是猜的话。 |
| 2 | **它不编。** 不捏造测量值、标准、引用、导入结果、你做过的操作，或完成声明。 | 它根本没读过 ISO 2768，却写"依据 ISO 2768"。 |
| 3 | **核验必须独立。** 只有用**独立于生成路径**的方法验过才算验过 —— 而且校验模型来自不同厂商家族。 | 模型给自己的作业打分。 |
| 4 | **它会反对你。** 反对的强度可配置；**但安全相关的反对不允许被关掉。** | 一个什么都说好的助手，放过了一个坏主意。 |
| 5 | **它承认边界，并指出谁能批。** 拒绝时会说清"需要哪一级权威才能做"，而不是只说"不行"。 | 悄悄降级，或者一个死胡同。 |
| 6 | **一切可审计。** 输入、计划、工具调用、版本、审批、策略、证据，全部防篡改留痕。 | "昨天还好好的"，然后没有任何东西可查。 |

## 它不会做什么

项目要声明自己的**行业**，行业决定这个项目里工作能走多远的**天花板** —— 决定的是走多远，
不是能不能开始。

- 提供十个领域：机械、制造、汽车、航空航天、土木、电气、建造、产品设计、建筑，以及*其他*。
- **R1 —— 概念工作照常进行。** 画个支架、出个渲染、改一版。
- **R2 及以上会被拒绝**，并说明需要哪一级权威才能放行。
- 记录一位**记名、可归属**的评审权威，可以把该领域抬到 R2 —— 而拒绝信息和产出上都会
  原样出现 **"RECORDED, NOT VERIFIED"** 这几个字，因为这套构建内部**没有**任何注册库
  可以去核验一张执业资质。
- **医疗和机器人什么都不允许。** 两者都不在选择器里。

这是有意为之。早期版本因为无法对"图纸放行"设闸门，就把**所有**工程领域包整个禁掉了 ——
结果连这个产品真正要服务的概念 CAD 也一起挡住了。一个机械工程师没法画一个支架，只因为
系统没能力给它做认证。

## 这个角色

FORGE 有一张脸，和一个标记，它们干的是两件事。

<div align="center">

<img src="internal/httpapi/assets/portrait/calm.png" width="96" alt="Calm">
<img src="internal/httpapi/assets/portrait/thoughtful.png" width="96" alt="Thoughtful">
<img src="internal/httpapi/assets/portrait/focused.png" width="96" alt="Focused">
<img src="internal/httpapi/assets/portrait/bright.png" width="96" alt="Bright">

*平静 · 思考 · 专注 · 明朗*

</div>

**肖像**是"存在感" —— 你在和谁一起工作。**标记（sigil）**是三片扫掠刀刃围着一个发光的
核心，它是"工作标记"：它承载**状态**，而且在表格行里 22px 下依然能读清楚 —— 那个尺寸下
一张脸只会糊成一团。

| 状态 | 标记的表现 | 含义 |
|---|---|---|
| Idle | 核心缓慢呼吸 | 没有待办 |
| Thinking | 脉动加快，刀刃微抬 | 一次模型调用正在途中 |
| Working | 一段弧沿着外环行进 | 有工具正在**这个进程之外**运行 |
| **Waiting for you** | 外环变成虚线门 | 停在边界上 —— **它在等你** |
| Stopped | 核心变暗，✕ | 目标以失败结束 |
| Done | 静止，✓ | 完成 |

每个状态都**不依赖颜色**就能区分 —— 靠运动、虚线样式和字形来传达含义。它始终表明自己
是 AI。

> 其中最要紧的是 *Waiting for you*：一个在等待却没人注意到的 agent，看起来和一个已经死掉的
> agent 一模一样，所以它被刻意做成了视觉上最突出的状态。

## 快速开始

**依赖：** Go 1.26+、Docker（用于本地 Postgres）、`make`。

```bash
git clone https://github.com/damonleelcx/J.A.R.V.I.S.-agent.git
cd J.A.R.V.I.S.-agent

cp .env.example .env
# 填入两个必需的密钥：
#   FORGE_SESSION_SECRET   openssl rand -base64 48
#   FORGE_LLM_API_KEY      你的 DashScope（通义千问）API Key

make db-up          # 在 :55840 启动 Postgres
make migrate        # 应用 schema（幂等，可重复执行）
make health         # 确认连通性
make check          # 格式检查、vet、完整测试套件
```

`make help` 列出所有可用目标。

## 底层是怎么搭的

```
用户目标 → Planner → 持久任务库 → 队列/调度器 → Agent Worker
             ↑                                        ↓
             └────── 重规划 ←── 检查点 ←── 校验 ←──── 工具
```

`Agent = 模型 + Harness + 持久状态 + 工作流引擎 + 工具 + 调度器 + 恢复 + 评测 + 可观测性`

有意思的不是这些方块，而是它们底下那三十多条决策 —— 为什么迁移链每次启动都全量重跑、
为什么校验模型必须来自不同厂商家族、为什么"遗忘"必须扛得住一个会把你删掉的事实重新学
一遍的 agent、为什么一次演练必须先证明自己注入的故障真的发生了。

**→ [docs/design-decisions.zh-CN.md](docs/design-decisions.zh-CN.md)** ——
每一条都写清了它替换掉了什么，以及走另一条路会出什么问题。

| 文档 | 用途 |
|---|---|
| [`docs/prd.md`](docs/prd.md) | 产品需求，含代码和测试引用的需求 ID |
| [`docs/architecture.md`](docs/architecture.md) | 各部分怎么拼在一起 |
| [`docs/design-decisions.zh-CN.md`](docs/design-decisions.zh-CN.md) | 为什么这么拼 |
| [`docs/security-promises.md`](docs/security-promises.md) | 保证了什么，以及没保证什么 |
| [`docs/bugfix/`](docs/bugfix) | 每个缺陷、它的根因，以及防它复发的那道围栏 |

## 发版

```bash
make release-check    # 格式、vet、跑在真 Postgres 上的完整测试、恢复演练、构建
make dist             # darwin / linux × amd64 / arm64 的交叉编译产物
make dist-verify      # 跑起构建产物，读它自己报出来的版本号
```

`.github/workflows/release.yml` 跑的就是同一条 `make release-check`，而不是在 YAML 里
重列一遍步骤——一个自己抄了一份检查清单的 workflow 迟早会和 Makefile 漂移，然后就会出现
「发版通过了一道谁也没法在本地跑的闸门」。

`dist-verify` 检查的是**产物，不是配方**。少了 `-ldflags` 编出来的二进制会报 `dev`，
一旦离开这台机器就和正式版没法区分，所以这条检查是把二进制跑起来，读它自己怎么说。

发版说明里会写清这个构建**做不到什么**，并指向 carried defects。一个看起来像成品的
下载页，本身就是一种不实陈述。

## 目录结构

```
cmd/forgectl/            运维 CLI：migrate、health、config、version
internal/platform/       跨领域基础设施
  config/                环境变量加载与校验
  db/                    Postgres 连接池、事务、迁移执行器
  db/sql/                迁移链（编译进二进制）
  errs/                  中央错误码注册表
  logx/                  结构化日志与事件名注册表
  id/                    带前缀、可按时间排序的标识符
  clock/                 可注入的时间源
docs/                    PRD、架构、决策记录
```

迁移通过 `//go:embed` 编译进二进制，且只存在于**一个**目录。
一个需要依赖同级目录才能跑迁移的二进制，就是一个可能被部署成"起不来"状态的二进制。

## 在 Go workspace 内构建

如果你把本仓库 clone 到一个存在上层 `go.work` 的目录树里，直接 `go build ./...` 会失败：

```
directory ... is contained in a module that is not one of the workspace modules
```

`Makefile` 已经设置了 `GOWORK=off`，所以 `make` 目标在两种情况下都能正常工作。
临时命令请自行前缀：`GOWORK=off go test ./...`
